# Основания и принятые решения

Использованы материалы из соседнего диалога «Объясни следующие шаги курсача»:
задание варианта 10, «Грамматика.docx», извлечённые разделы методички
«Metod_ТЯПиМТ_курс (2).doc» и созданные там `variant10/Грамматика.md`,
`variant10/build_table.py`. Исходный лексер взят из вложения текущего диалога.

Методичка, раздел лабораторной работы № 3: программа состоит из объявления
переменных, затем описания вычислений; присваивание и объявление заканчиваются
точкой с запятой. Для варианта 10 установлен восходящий распознаватель,
тип LOGICAL, константы 0/1, длина имени 8, логические операции с точками.
Определение буквы — A–Z; поэтому строчные имена из исходного лексера теперь
отклоняются. Числовые коды токенов и индексы таблиц сохранены.

Раздел 2.2 добавляет READ, REPEAT, WRITE. В REPEAT используется список
присваиваний; вложенные циклы и ввод/вывод в его теле не допускаются.
В методичке после WRITE стоит точка. В ранее согласованной исправленной
грамматике принят единый `;` для всех команд; это соглашение сохранено явно.

Раздел 2.3 требует магазинный автомат, сообщения об ошибках и промежуточную
форму программы. Реализован SLR(1) — разновидность восходящего табличного
разбора. Промежуточная форма — дерево разбора, пригодное для следующего этапа.
Формализация ПОСЛЕ как непосредственного соседства терминалов и СВЕРТ как
соответствия правой части правила его номеру сохранена из предыдущего расчёта;
таблица ACTION/GOTO строится непосредственно по SLR(1).

Исходная грамматика имела недостижимые READ/REPEAT/WRITE, пропуски разделителей,
обратный порядок объявления и блока, неоднозначные выражения. Реализация
использует исправленную версию из соседнего диалога. Приоритеты выражены
отдельными нетерминалами; равные бинарные операции связываются слева, как
принято на предыдущем этапе. Повторное NOT разрешено правилом Unary → NOT Unary.

Репозиторий [PLTaTM](https://github.com/MiserLies17-23/PLTaTM) изучен как пример
организации компонентов: отдельные лексический и синтаксический анализаторы,
грамматика, токены и диагностика. Его C#-реализация не копировалась.
Генератор таблицы переиспользован из собственного предыдущего этапа проекта.

Изменение грамматики делается в `tyap/grammar/rules.py`. При запуске таблица
строится из этих правил; конфликт вызывает ValueError, вместо скрытого выбора
переноса или свёртки. После изменения нужно обновить документацию командой
`python -m tyap.grammar.table` и выполнить тесты. Генератор рассчитан на текущую
грамматику без пустых продукций, а не на произвольную контекстно-свободную грамматику.
