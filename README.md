# TYAP

Лексический и синтаксический анализатор учебного языка, вариант 10.
Python 3.10+, без сторонних библиотек. Разработан на основе предоставленного
лексера и исправленной грамматики из предыдущего этапа работы.

## Запуск

Откройте папку TYAP как проект PyCharm и запустите `main.py` или конфигурацию
**TYAP**. Без аргументов анализируется исправленный пример программы.
Команды ниже выполняются из корня проекта:

```console
python main.py
python -m tyap examples/valid/program.tyap --tokens --tree
python -m tyap examples/valid/precedence.tyap --trace
python -m tyap examples/valid/program.tyap --tree-output tree.txt
python -m tyap examples/invalid/original.tyap
python -m tyap -
python -m unittest discover -v
python -m tyap.grammar.table
```

Последняя команда заново создаёт `docs/table.json` и `docs/Таблица.md`:
55 состояний, ACTION/GOTO, правила свёртки, ПЕРВ/СЛЕД/ПОСЛЕ/СВЕРТ и ситуации LR(0).
Коды завершения: 0 — успешный разбор, 1 — ошибка языка, 2 — ошибка файлового ввода/вывода.
Файлы читаются в UTF-8, допускается BOM. Для stdin используется кодировка терминала Python.

## Правила языка

```text
VAR A, B:LOGICAL;
BEGIN
    READ(A);
    B = .NOT. A .OR. 1;
    REPEAT
        A = B;
    UNTIL A;
    WRITE(A, B);
END
```

Имена — от 1 до 8 букв `A`–`Z`; регистр значим. Константы — только `0` и `1`.
Приоритеты: `.NOT.` > `.AND.` > `.OR.` > `.IMP.`. Бинарные операции
левоассоциативны. Скобки меняют группировку. Блок непустой, внутри REPEAT
разрешены только одно или несколько присваиваний. Комментарии не предусмотрены.

Исходный пример пользователя хранится в `examples/invalid/original.tyap`
без артефактов форматирования сообщения (`\` и `&#x20;`). Он намеренно
отклоняется: `1D` и `B1` недопустимы, операции должны иметь точки, а объявление
должно предшествовать BEGIN и заканчиваться `;`. Исправленный пример находится
в `examples/valid/program.tyap`; в нём `1D` заменено на `D`, а `B1` на `B`.

## Как устроен анализ

Лексер сохраняет коды токенов, позиции и индексы таблиц символов из исходной
реализации. При наличии лексических ошибок синтаксический этап не запускается.
Парсер читает токены и управляет двумя стеками: состояний и узлов дерева.
ACTION выбирает перенос, свёртку или допуск, GOTO задаёт состояние после свёртки.
Отсутствие действия означает ошибку; выводятся координаты и ожидаемые терминалы.
После первой синтаксической ошибки разбор прекращается.

Промежуточное представление — конкретное дерево разбора (CST), включающее
номера правил, терминалы и исходные координаты. `--trace` показывает состояния
перед каждым действием. `sN` — перенос в N, `rN` — свёртка по правилу N,
`ok` — допуск. Номера соответствуют `docs/Таблица.md`.

Проверка объявлений, вычисление выражений и выполнение READ/WRITE/REPEAT относятся
к последующим этапам транслятора и здесь не реализованы. Успешный разбор означает
только лексическую и синтаксическую корректность.

Подробности: [грамматика](docs/grammar.md), [таблица автомата](docs/Таблица.md),
[связь с методичкой](docs/decisions.md).
