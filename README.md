# TYAP — анализатор учебного языка, вариант 10

TYAP проверяет исходную программу в два этапа. Лексер делит текст на токены и собирает таблицы идентификаторов и констант. Синтаксический анализатор проверяет порядок токенов по грамматике и строит дерево разбора. По запросу программа показывает токены, шаги автомата и абстрактное синтаксическое дерево.

## 1. Теория

### 1.1. Лексемы, токены и таблицы символов

**Лексема** — фрагмент исходного текста, который распознал лексер. Например, в `A = 1;` четыре лексемы: `A`, `=`, `1`, `;`. **Токен** хранит вид лексемы, её текст, номер строки и столбца, а для идентификатора или константы ещё и индекс в соответствующей таблице.

| Группа | Что распознаёт лексер |
| --- | --- |
| Ключевые слова | `BEGIN`, `END`, `VAR`, `LOGICAL`, `READ`, `WRITE`, `REPEAT`, `UNTIL` |
| Логические операции | `NOT`, `AND`, `OR`, `IMP` |
| Разделители и знак присваивания | `;`, `=`, `(`, `)`, `,`, `:` |
| Идентификаторы | Последовательности латинских букв `A–Z` и `a–z`. Регистр учитывается, поэтому `A` и `a` — разные имена |
| Константы | `0` и `1` |
| Служебные токены | `EOF` обозначает конец входа, `INVALID` отмечает лексическую ошибку |

Лексер считывает слово целиком, а затем проверяет его вид. Поэтому `READ` — ключевое слово, `READA` — идентификатор, а `B1` — одна ошибочная лексема. Ключевые слова распознаются в верхнем регистре. Пробелы и переводы строк разделяют лексемы и участвуют в расчёте координат.

Выражение `token.pair` даёт пару «числовой код вида, индекс в таблице». Например, первый встреченный идентификатор получает пару `(100, 0)`, а первая константа — `(101, 0)`. Индексы начинают отсчитываться с нуля отдельно в каждой таблице. Повторное вхождение той же лексемы сохраняет индекс. У ключевых слов и разделителей индекс равен `None`. Таблица идентификаторов показывает, какие имена встречены в исходнике, а список в объявлении `VAR` формируется на синтаксическом этапе.

### 1.2. Контекстно-свободная грамматика

Грамматику можно задать как `(V, T, R, I)`. Здесь `V` — множество нетерминалов, `T` — множество терминалов, `R` — правила вывода, а `I` — начальный нетерминал. Терминал соответствует токену языка. Нетерминал обозначает конструкцию, например выражение или блок. В каждом правиле слева стоит один нетерминал, поэтому грамматика контекстно-свободная.

В таблице используется вспомогательное правило `Start → I`. В записи правил `→` читается как «заменить левую часть правой», а `|` разделяет альтернативы.

```text
I → A B
A → BEGIN P END
B → VAR C : LOGICAL
C → L | L , C
P → E | E P | O | O P
D → E | E D
E → L = F ;
F → H G | G
G → ( F ) | K | G J G
H → NOT
J → AND | OR | IMP
K → L | M
L → ID
M → 0 | 1
O → READ ( C ) ; | REPEAT D UNTIL F ; | WRITE ( C ) ;
```

| Нетерминалы | Значение |
| --- | --- |
| `I`, `A`, `B` | Программа, основной блок, объявление переменных |
| `C`, `P`, `D` | Список имён, список команд в основном блоке, список присваиваний внутри цикла |
| `E`, `O` | Присваивание, одна из команд `READ`, `REPEAT`, `WRITE` |
| `F`, `G` | Выражение и подвыражение |
| `H`, `J` | Унарная и бинарная логические операции |
| `K`, `L`, `M` | Операнд, идентификатор, константа |

В исходной записи `L → N L | N` описывает имя как последовательность букв. В реализации лексер уже собрал имя в один токен, поэтому таблица использует `L → ID`. Токены `CONSTANT` по своему тексту становятся терминалами `0` или `1`.

Разворачивая правила от `I`, можно получить, например, такую цепочку. Запись `⇒*` обозначает несколько шагов вывода.

```text
I ⇒ A B ⇒ BEGIN P END B ⇒ BEGIN E END B
  ⇒ BEGIN L = F ; END B
  ⇒* BEGIN ID = 1 ; END VAR ID : LOGICAL
```

Объявление располагается после `END`. Точка с запятой завершает присваивание, `READ`, `WRITE` и условие после `UNTIL`. Правила `P`, `D` и `C` задают непустые списки. В теле `REPEAT` разрешены присваивания, а после `UNTIL` требуется выражение.

### 1.3. Логические операции и неоднозначность

`NOT` меняет значение `0` на `1` и наоборот. Для бинарных операций значения определяются так.

| A | B | A AND B | A OR B | A IMP B |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | 0 | 1 |
| 0 | 1 | 0 | 1 | 1 |
| 1 | 0 | 0 | 1 | 0 |
| 1 | 1 | 1 | 1 | 1 |

Правило `G → G J G` допускает несколько деревьев для одной цепочки. Например, `A OR B AND C` можно сгруппировать как `(A OR B) AND C` или `A OR (B AND C)`. Анализатор выбирает вторую группировку, поскольку `AND` сильнее `OR`. Порядок бинарных приоритетов — `AND > OR > IMP`. Операции равного приоритета группируются слева, поэтому `A IMP B IMP C` означает `(A IMP B) IMP C`.

Область действия `NOT` задаёт правило `F → H G`. Выражение `NOT A OR B` в этой грамматике разбирается как `NOT (A OR B)`. Чтобы отрицать только `A`, используется запись `(NOT A) OR B`.

### 1.4. Восходящий разбор и магазинный автомат

Восходящий анализатор читает вход слева направо и собирает из терминалов конструкции более высокого уровня. Сборка конструкции называется **свёрткой**. Например, если вершину магазина занимает цепочка `L = F ;`, её можно свернуть в `E` по правилу присваивания. В результате успешного разбора в магазине получается начальный символ `I`.

У автомата два стека. Первый хранит состояния. Второй содержит узлы дерева, каждый из которых соответствует символу грамматики. Изначально в первом стеке находится состояние `0`, а второй пуст. На каждом шаге автомат смотрит на состояние на вершине и на текущий входной токен.

| Запись | Действие автомата |
| --- | --- |
| `sN` | Перенос. Положить узел токена и состояние `N` на соответствующие стеки, перейти к следующему токену |
| `rN` | Свёртка по правилу `N`. Снять узлы правой части и столько же состояний, собрать узел левой части и перейти по `GOTO`. Позиция на входе сохраняется |
| `ok` | Принять вход. В текущей таблице это происходит при `EOF` из состояния `3`, когда построен узел `I` |
| Пустая ячейка | Сообщить о синтаксической ошибке для текущего токена |

### 1.5. Построение ACTION и GOTO

Генератор строит таблицу методом **SLR**, используя состояния из ситуаций LR(0) и множества `СЛЕД` для свёрток. Ситуация — это правило с точкой в правой части. Например, `A → BEGIN · P END` означает, что `BEGIN` уже распознан и дальше ожидается список команд `P`.

1. **Начальное состояние.** Берётся ситуация `Start → · I`. Если после точки стоит нетерминал, в состояние добавляются его правила с точкой в начале. Такое пополнение называется **замыканием**. Для состояния `0` замыкание добавляет `I → · A B` и `A → · BEGIN P END`.
2. **Переходы.** Чтобы построить переход по символу, генератор сдвигает точку вправо за этот символ во всех подходящих ситуациях, затем вычисляет замыкание результата. Переход по терминалу даёт перенос в `ACTION`, а переход по нетерминалу записывается в `GOTO`. Например, `ACTION[0, BEGIN] = s2`, а `GOTO[0, A] = 1`.
3. **Свёртки.** Точка в конце правила `X → α ·` означает, что его правую часть можно собрать в `X`. Генератор записывает свёртку в `ACTION` по токенам из `СЛЕД(X)`. Для завершённой ситуации `Start → I ·` записывается `ok` по `EOF`.
4. **Конфликт переноса и свёртки.** В состоянии `53` есть и `G → G J G ·`, и `G → G · J G`. Например, для `AND` в ячейке записано `r17/s44`. Во время разбора автомат сравнивает `AND` с операцией `J` на стеке. Если входная операция сильнее, происходит перенос. Иначе выполняется свёртка. Для `A OR B AND C` перенос позволяет сначала собрать `B AND C`.

В проекте используются следующие множества и отношения.

| Обозначение | Как читать | Пример |
| --- | --- | --- |
| `ПЕРВ(X)` | Терминалы, с которых может начинаться вывод из `X` | `ПЕРВ(F) = { (, 0, 1, ID, NOT }` |
| `СЛЕД(X)` | Терминалы, которые могут стоять сразу после `X` в выводимой цепочке | `СЛЕД(F) = { ), ; }`, потому что выражение встречается в скобках и перед концом команды |
| `ПОСЛЕ(t)` | Терминалы, которые могут идти сразу за терминалом `t` в корректном входе | `ПОСЛЕ(END) = { VAR }` |
| `СВЕРТ(α)` | Правила, у которых цепочка `α` является правой частью | Для `E` возможны `r6: P → E` в основном блоке и `r10: D → E` внутри цикла. Выбор зависит от состояния и следующего токена |

В грамматике отсутствуют пустые продукции. Поэтому `ПЕРВ` левой части пополняется из `ПЕРВ` первого символа правой части. Для `СЛЕД` генератор берёт `ПЕРВ` следующего символа или `СЛЕД` левой части, если рассматриваемый нетерминал стоит последним. Расчёт повторяется, пока множества перестают расти. Для `ПОСЛЕ` берутся пары из `ПОСЛЕДНИЕ(X) × ПЕРВ(Y)` для соседних `X Y` в правилах.

В текущей таблице **57 состояний**. Полные множества, переходы, номера правил и ситуации по состояниям приведены в [таблице автомата](docs/Таблица.md).

### 1.6. Дерево разбора и AST

**Дерево разбора** показывает применённые продукции. При переносе создаётся лист с токеном и координатами, при свёртке — узел с нетерминалом, номером правила и дочерними узлами. Например, ветка присваивания хранит `L`, `=`, `F` и `;`.

**Абстрактное синтаксическое дерево (AST)** сохраняет структуру программы на уровне блоков, команд и выражений. Узел `Assignment` содержит имя и правую часть, `REPEAT` содержит тело и условие, а `Binary AND` содержит два операнда. Скобки влияют на структуру дерева, а разделители и служебные уровни грамматики убираются при преобразовании.

## 2. Как работает программа

### 2.1. Запуск и параметры

Требуется Python 3.10 или новее. Сторонних зависимостей нет. В PyCharm откройте проект и запустите файл `main.py`. В терминале выполняйте команды из корня проекта.

```console
python main.py
python -m tyap examples/valid/program.tyap --tokens --tree
python -m tyap examples/valid/precedence.tyap --trace
python -m tyap examples/valid/program.tyap --tree-output tree.txt
```

Без пути программа берёт `examples/valid/program.tyap`. Для чтения из стандартного ввода передайте `-` вместо пути. Файлы исходного текста читаются в UTF-8, в том числе с BOM.

| Параметр | Результат |
| --- | --- |
| `--tokens` | Печатает токены с кодами, координатами и индексами, затем таблицы идентификаторов и констант |
| `--trace` | Показывает позицию во входе, оба стека, текущую лексему и выбранное действие |
| `--tree` | Печатает AST в консоли |
| `--tree-output tree.txt` | Сохраняет AST в текстовый файл UTF-8 |

### 2.2. Порядок вызовов в коде

1. `main.py` или `tyap/__main__.py` передаёт управление функции `main()` из `tyap/cli.py`. Она читает параметры и исходник.
2. `Lexer.scan()` проходит по символам, ведёт координаты, формирует список токенов и добавляет `EOF`. Идентификаторы и константы попадают в две таблицы символов. При лексических ошибках интерфейс выводит все найденные сообщения и завершает обработку.
3. `Parser()` строит таблицы через `build()` из `tyap/grammar/table.py`. Источником продукций служит `tyap/grammar/rules.py`. Сохранённые таблицы в `docs/` используются для пояснения расчёта и сверки.
4. `Parser.parse()` обрабатывает токены до допуска или первой синтаксической ошибки. Метод `_choose_action()` разрешает конфликт для логических операций, а `_reduce()` снимает правую часть со стеков, строит узел и делает переход по `GOTO`.
5. Если пользователь запросил дерево, `build_ast()` из `tyap/syntax/nodes.py` преобразует дерево свёрток. `Node.lines()` форматирует его как строки с отступами. После успешного разбора интерфейс печатает итоговое сообщение.

### 2.3. Разбор небольшого примера

```text
BEGIN A=1; END VAR A:LOGICAL
```

В PowerShell тот же пример можно сразу передать на вход.

```powershell
'BEGIN A=1; END VAR A:LOGICAL' | python -m tyap - --tokens --trace --tree
```

Лексер выдаёт цепочку `BEGIN ID = 1 ; END VAR ID : LOGICAL EOF` в обозначениях таблицы разбора. Оба вхождения `A` ссылаются на идентификатор с индексом `0`. Значение `1` находится под индексом `0` в таблице констант.

Ниже приведены выбранные строки трассировки. Стек показан **до** действия, правое состояние находится на вершине. `A` в столбце символов после `r2` — нетерминал блока, а `A` во входе — имя переменной.

| Стек состояний | Стек символов | Следующая лексема | Действие |
| --- | --- | --- | --- |
| `0` | — | `BEGIN` | `s2` |
| `0 2` | `BEGIN` | `A` | `s7` |
| `0 2 7` | `BEGIN ID` | `=` | `r24: L → ID` |
| `0 2 8` | `BEGIN L` | `=` | `s17` |
| `0 2 8 17 28` | `BEGIN L = 1` | `;` | `r26: M → 1` |
| `0 2 8 17 29 43` | `BEGIN L = F ;` | `END` | `r12: E → L = F ;` |
| `0 2 10 19` | `BEGIN P END` | `VAR` | `r2: A → BEGIN P END` |
| `0 1 5 14 24 40` | `A VAR C : LOGICAL` | `EOF` | `r3: B → VAR C : LOGICAL` |
| `0 1 4` | `A B` | `EOF` | `r1: I → A B` |
| `0 3` | `I` | `EOF` | `ok` |

На шаге `r24` после снятия `ID` и состояния `7` открывается состояние `2`. Переход `GOTO[2, L] = 8` даёт стек `0 2 8`. Текущий токен по-прежнему `=`, и только следующим действием автомат его переносит.

Вывод `--tree` для этого текста выглядит так.

```text
Program
  Block
    Assignment
      ID 'A' [1:7]
      1 '1' [1:9]
  Declaration LOGICAL
    ID 'A' [1:20]
```

### 2.4. Полный пример с вводом, циклом и выводом

```text
BEGIN
    READ(A, B);
    C = A AND B;
    D = NOT A OR B;
    REPEAT
        A = A OR B;
        C = A IMP D;
    UNTIL C;
    WRITE(A, B, C, D);
END
VAR A, B, C, D:LOGICAL
```

В [рабочем примере](examples/valid/program.tyap) узел `Program` имеет двух потомков: `Block` и `Declaration LOGICAL`. В блоке по порядку находятся `READ`, два присваивания, `REPEAT` и `WRITE`. У `REPEAT` один потомок `Body` с двумя присваиваниями, а второй — идентификатор `C` из условия. Проверка объявлений, вычисление выражений и выполнение команд относятся к следующим этапам транслятора. Здесь результатом служит структура программы.

### 2.5. Диагностика

| Что проверяется | Пример |
| --- | --- |
| Лексическая корректность | В [исходном ошибочном примере](examples/invalid/original.tyap) лексер указывает на `1D` и `B1`. Цифра в начале `1D` приводит к сообщению о недопустимой константе, а `B1` — о недопустимом идентификаторе |
| Синтаксическая корректность | В [примере без точки с запятой](examples/invalid/missing_semicolon.tyap) парсер встречает `END` на строке 3, столбце 1. Он выводит терминалы из строки `ACTION` текущего состояния, в том числе ожидаемый `;` |
| Чтение и запись | Неверный путь или ошибка кодировки приводят к сообщению об ошибке файла |

Коды завершения: `0` при успешном разборе, `1` при лексической или синтаксической ошибке, `2` при ошибке файлового ввода или вывода. Ошибка параметров командной строки тоже даёт `2`.
